**A failure worth recording:** the first version of this spike ran as PGlite's built-in
superuser and **all seven policy checks failed** — rows from every tenant were visible.
Superusers bypass RLS even with `FORCE ROW LEVEL SECURITY`. The spike now creates
`app_runtime` (NOLOGIN, NOINHERIT, no BYPASSRLS, not the table owner) and runs everything
through `SET LOCAL ROLE`. This is the single most important finding of M2 so far: the
migration greps and CI checks are necessary but **not sufficient** — the connection role
is equally part of the control.

## 7. Security findings

- RLS is enforced only for non-privileged roles; the runtime role must never own tables or
  hold `BYPASSRLS` (now proven, not assumed).
- `FORCE` does not protect against superusers; it protects against table owners.
- Hosting on Workers+Hyperdrive would forbid session-level advisory locks and SQL-level
  prepared statements; the chosen architecture avoids both (ADR-0001, ADR-0002).
