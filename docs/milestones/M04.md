# M04 — Migration runner, authentication, sessions, `/api/v1`

Date: 2026-11-21 · Status: **in-progress** — runner, login/session/logout and six v1
routes are done and verified against a real PostgreSQL engine; MFA, Kysely and a live
pool remain

## 1. Completed work

**Migration runner with checksums** (`packages/data/src/migrator.ts`, `tools/migrate.mjs`)

- `NNNN_lower_snake.sql`, versions contiguous from `0001`, one transaction per file with its
  ledger row inside that same transaction.
- sha256 recorded in `mbs_meta.schema_migrations`; an edited applied file fails the run
  instead of leaving two different databases behind.
- A migration file may not contain `BEGIN`/`COMMIT` — the runner owns the transaction.
- `--status`, `--check`, `--dry-run`; `pg_advisory_xact_lock` so two runners cannot interleave.
- `tools/verify-schema.mjs` now applies migrations through the runner, so the ordering and
  checksum rules are exercised on every `npm run verify`.

**Database port** (`packages/data/src/db.ts`)

- `Db`/`Tx` interface with a PGlite adapter (tests) and a `pg` pool adapter (production),
  plus `withTenant()` and `withCapability()`.

**Authentication** (`db/migrations/0002_auth.sql`, `packages/domain/src/auth/`,
`apps/api/src/auth.ts`)

- Argon2id via hash-wasm, 19 MiB / t=2 / p=1, 16-byte salt, 32-byte output, PHC-encoded so
  the cost can be raised later without invalidating hashes.
- 256-bit opaque session token; only its sha256 is stored (`tenant.sessions.token_hash`);
  cookie is `HttpOnly; SameSite=Strict; Secure; Max-Age=28800`.
- Login throttle keyed by `sha256(lower(email))` — the table holds no addresses. 5 failures
  locks the address for 15 minutes; a successful login clears the counter; a lock that has
  expired restarts the count.
- Missing accounts run a real Argon2id verification against a dummy hash, so login timing
  does not reveal whether an address exists.
- Two additive SELECT-only capability policies (ADR-0015) answer "which row is this token /
  this user", never "which tenant".
- Business selection: 0 active memberships → 403; exactly 1 → used; more than 1 without a
  slug → 409 with the list; a slug the account has no membership in → 403.

**API** (`apps/api/src/`)

| Method | Path | Notes |
|---|---|---|
| GET | `/api/v1/health` | no session, no data |
| POST | `/api/v1/auth/login` | sets the session cookie |
| POST | `/api/v1/auth/logout` | revokes the row, clears the cookie, audit entry |
| GET | `/api/v1/me` | user, active business, role, permissions |
| GET | `/api/v1/org` | business profile |
| PATCH | `/api/v1/org` | owner/manager only, whitelisted fields, before/after audit |
| GET | `/api/v1/openapi.json` | OpenAPI 3.1, generated from the route table |

Every response: `cache-control: no-store`, CSP `default-src 'none'`, no framing, no
referrer, `nosniff`, `x-request-id` (the id that appears in `audit_log.request_id`). Bodies
are JSON only (415 otherwise), capped at 16 KiB, and unknown patch fields are a 400 rather
than being ignored.

## 7. Security findings

- **A parameter-type bug became a test.** A single `$1` used for both a `uuid` column and a
  `text` column made PostgreSQL deduce two types; it surfaced as a 500 on the profile update
  and is now a separate parameter. The audit test asserts the row, not just the status.
- **Capability policies are narrower than a definer function.** They cannot return a
  tenant's other rows, and the static checker now rejects a capability policy that is not
  SELECT.
- **Enumeration:** unknown email, wrong password and locked account all return 401/429 with
  the same message; the unknown-email path still pays for an Argon2id verification.
- **Cookie scope:** `Path=/`, no `Domain` attribute — a future subdomain cannot read it.

## 9. Known limitations

- **Kysely is not wired.** ADR-0002 chose Kysely + `pg`; the request path currently uses the
  `Db` port with hand-written SQL and no query builder. Swapping in Kysely behind the same
  port is a contained change, but it cannot be verified without a real server, and unverified
  database code is worse than explicit SQL.
- **No MFA yet.** `mfa_enrolled_at` is read by the login path and ignored; TOTP, passkeys and
  recovery codes are the next M4 work unit.
- **Concurrency is still unproven.** PGlite is one connection: pool behaviour, interactive
  transactions and two simultaneous logins remain `blocked` (R-032, R-035).
- **No `typescript` compiler in CI**, so types are erased by Node's type stripping and are
  not checked. Adding `tsc --noEmit` is a small follow-up once the toolchain is pinned.
- **Trailing negotiation:** `PATCH /org` writes `updated_at` without optimistic concurrency;
  two simultaneous saves last-write-wins. Revisit with the first real settings screen.

## 10. Risks

R6 (tenant isolation) now has an API-level half: the business comes from the session and a
body `tenant_id` is rejected. R7 (session theft) is reduced by hashing tokens at rest, but
there is no device list or "sign out everywhere" yet — that belongs to the account screens.

## 11. Rollback

Migrations are additive (`0002` adds one table, five functions and two policies). Rolling
back means dropping those objects; no M3 data is touched.
