# M05 — First owner screens: sign in and business profile

Date: 2026-11-21 · Status: **in-progress** — sign-in and business profile are built,
localized and verified; the remaining owner screens come next

## 1. Completed work

**Portal application** (`apps/web`, React 19 + Vite 8, ADR-0016)

- One static bundle served by the API at the same origin, so the session cookie stays
  `SameSite=Strict; HttpOnly` and no token is ever held in JavaScript.
- `App` boots by asking `/api/v1/me`; the session is never trusted from storage. A 401 shows
  the sign-in screen, and a session that expires mid-edit returns to it with
  `auth.sessionExpired` rather than a blank page.

**Sign-in screen**

- Email + password, show/hide password, required-field errors tied by `aria-describedby`,
  a live error banner and a busy button label.
- Server errors are mapped by status/code, never echoed: 401 → "Email or password is
  incorrect", 429 → the lock message with the retry delay rounded to minutes and an ICU
  plural, 403 → permission denied, 0 → offline.
- Multiple businesses: the 409 body's list becomes a radio group, and the second submit
  carries `tenant_slug`; the server remains the only authority on which businesses exist.
- The session's own expiry (“8 hours”) is stated up front.

**Business profile screen**

- Loads `/api/v1/org` for the session's business; no id is sent or accepted from the URL.
- Owners and managers edit; accountants and employees get the same screen read-only with
  an explanation, so anyone can check what is on file.
- Fields: legal name, BIN, address, phone, email, digit style, fiscal-year start month, VAT
  registration; currency and time zone are shown read-only because v1 supports only BDT and
  Asia/Dhaka.
- Only changed fields are PATCHed, trimmed, with empty optional text sent as `null`. The
  server's audit row therefore shows a real diff.
- Unsaved-changes protection: `beforeunload` while dirty, and Cancel asks before discarding.
- Save states: busy label, translated success banner (`role="status"`), error banner
  (`role="alert"`); a 401 mid-save returns to sign-in.

**Bengali and English from the first screen**

- 85 messages in each catalog, the same ids and the same ICU placeholders.
- Header and sign-in both switch language; the choice is remembered, and `?lang=bn` wins so
  a link can be shared in the intended language.
- Bangla changes `<html lang>` and line height; digits come from the business's
  `numbering_system` setting, with Bengali or Latin numerals and lakh/crore grouping.
- Every date is rendered for `Asia/Dhaka` through one formatter.
- The font stack prefers a real Bangla face (Noto Sans Bengali, Nirmala UI, Hind Siliguri,
  SolaimanLipi) before `system-ui`; a self-hosted webfont is deferred (see limitations).
- `tools/check-i18n.mjs` fails `npm run verify` on a missing translation, a mismatched
  placeholder, an unknown message id, or literal JSX text / `placeholder` / `aria-label` /
  `title` / `alt` values.

**Development and hosting**

- `npm run dev:api` (in-memory PGlite, real migrations, four demo accounts) and
  `npm run dev:web` (Vite proxy to :4000) give a complete local portal.
- `npm run build:web` produces the bundle; `MBS_WEB_ROOT=apps/web/dist` makes the API serve
  it, with SPA fallback, immutable caching for `/assets/`, `no-store` for the HTML and its own
  CSP. Path traversal is refused and tested.

## 7. Security findings

- **No session material in the client.** The cookie is `HttpOnly`; the bundle holds no
  token, and `localStorage` stores only the language.
- **Errors are codes, not server prose.** A screen maps `invalid_credentials`,
  `too_many_attempts`, 403 and 0 to catalog messages; an unexpected body cannot become UI
  text.
- **The browser cannot choose a business.** `tenant_slug` exists only on login and only
  after the server listed it; every later call is scoped by the session.
- **Static handler:** decoded paths are resolved and prefix-checked against the build root,
  `/api/` is never served as a file, missing assets are 404 (not the shell), and the portal
  has its own CSP with `connect-src 'self'` and no inline script.
- **Demo data:** `tools/dev-api.mjs` refuses nothing but prints that the password is demo
  only; it cannot be pointed at a real database because it creates an in-memory one.
- **No font or analytics request leaves the page.** `connect-src`, `font-src` and
  `img-src` are all `'self'` (or `data:` for images); the device's own Bangla font is used.

## 9. Known limitations

- **Two screens only.** No router yet; the profile is the landing screen, and navigation
  appears with the third screen.
- **No second factor in the UI.** The login endpoint already reads `mfa_enrolled_at`, but
  TOTP/passkeys are still unbuilt (R-045), so the screens do not offer them.
- **No session list or "sign out everywhere".** Logout revokes the current session only.
- **No optimistic concurrency** on the profile: two simultaneous saves last-write-wins.
- **No DOM tests.** Pure logic (catalogs, client, diffing) is tested; components are covered
  by type-checking and the build, not by a rendered test.
- **The i18n gate is a regex checker, not ESLint's `no-restricted-syntax`** (ADR-0008). It
  covers JSX text and the five text attributes; a string built at runtime from a literal
  could still slip through.
- **The Bangla webfont is not bundled.** The page relies on a Bangla face installed on the
  device; a machine with none falls back to `system-ui` and may show boxes. A self-hosted
  Noto Sans Bengali (SIL OFL) is the intended fix, but this session's push channel carries
  text only and the file is binary.
- **Latin typeface is system Inter if installed, otherwise `system-ui`**; Inter is not
  bundled yet.
- **Dark mode follows the OS only**; there is no in-app theme switch.

## 10. Risks

R6 (tenant isolation) now has its UI half: no screen can name a business, and the chooser
only reflects the server's 409 list. R7 (session theft) is unchanged; MFA is the next control.

## 11. Rollback

Remove `apps/web`, `apps/api/src/static.ts` and the `webRoot` option; the API then behaves
exactly as in M4. No migration to reverse. The font files and React/Vite dependencies can be
dropped with the app.

## 12. Prerequisites for M6

- TOTP enrolment and recovery codes before real owners are invited (R-045).
- Session listing / revoke-all, so a lost phone can be cut off.
- A router decision once the third screen exists (ADR-0016 defers it deliberately).
- Decide whether the next screens are the dashboard shell or continue the settings area.
