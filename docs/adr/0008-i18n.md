# ADR-0008 — Internationalisation, locale data and Bangla numerals

**Status:** Accepted · **Date:** 2026-11-21 · **Class:** D1 · **Reversibility:** high

## Context

Legacy ships three message trees: `en` (1,489 lines), `bn` (1,481), `ar` (1,481). The
master prompt names only Bangla + English. Spec 9.5 requires the framework from the first
screen, a lint rule banning hardcoded strings, `Intl` with `bn-BD`/`en-BD`, a setting for
Bangla vs Latin digits, lakh/crore grouping, and Asia/Dhaka rendering.

## Options considered

| Option | Assessment |
|---|---|
| `react-i18next` | Huge ecosystem, but its plural/format story is its own mini-language; ICU compatibility is partial. |
| **`@formatjs/intl` + ICU MessageFormat** | Standard message syntax (`{count, plural, …}`), first-class `Intl`, TS type generation from the catalogs, works in tests without a React tree. |
| Hand-rolled dictionary | What legacy does (a custom `translator.ts` with path lookup); no pluralisation, no formatting. |

## Decision

ICU MessageFormat via `@formatjs/intl`:
- Catalogs live in `packages/config/i18n/{en,bn}.json`, one flat namespace per domain.
- Message ids are dotted and stable (`invoices.list.title`), never English text as the key.
- `Intl.NumberFormat('bn-BD')` / `'en-BD'`, `Intl.DateTimeFormat`, `Intl.PluralRules`.
- A per-business setting `numbering_system: 'bengali' | 'latin'` controls digits; PDFs
  follow the same setting.
- Currency formatting uses the `৳` symbol with the business's digit preference, but
  **stored and transmitted values are always ASCII decimal strings** (ADR-0003).
- A lint rule (`no-restricted-syntax`) fails on string literals inside JSX text nodes.
- `ar` is **not** shipped in v1 (see ADR-0011); the file is retained in OLD as reference.

## Consequences

- Bengali collation and sorting need an explicit `COLLATE` choice in PostgreSQL; ICU
  collation for `bn` is evaluated during M3 with a real dataset.
- The legacy translated *business wording* is a valuable asset: copy `bn`/`en` strings
  into the new catalogs where the module is preserved, recording them in `ORIGINS.md`.
- Every date shown to a user passes through one formatter with `Asia/Dhaka`.
