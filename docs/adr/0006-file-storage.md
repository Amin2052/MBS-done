# ADR-0006 — File storage

**Status:** Accepted · **Date:** 2026-11-21 · **Class:** D1 · **Reversibility:** medium
(object keys are stable; the backend behind them can change)

## Context

Uploads: business logos, product images, expense receipts, invoice attachments, employee
documents, generated PDFs, ETL source copies. Legacy stores product images inside the
app's own filesystem (`images/product_thumb`, base64 in the renderer), which does not
scale to a multi-tenant server and is one more reason the desktop app cannot simply be
lifted to the web.

Rules that follow from the spec: files are tenant data (never public), downloads are
short-lived and authorised per request, and PDPO obligations (deletion, export) apply to
files too.

## Options considered

| Option | Assessment |
|---|---|
| Files on the API server's disk | Simplest, but breaks horizontal scaling, needs shared storage for the worker, and complicates backup/restore. |
| Database `bytea` | Transactional with metadata, but bloats the database, backups and replication; large PDFs hurt the pool. |
| **S3-compatible object storage** | Durable, cheap, presigned URLs, lifecycle rules, versioning; works with AWS S3, R2, MinIO (local). |

## Decision

S3-compatible object storage through one `Storage` interface (`put`, `get`, `delete`,
`presign`, `copy`, `listPrefix`), with the AWS SDK client pointed at whatever endpoint
the environment provides.

- Key layout: `tenant/<tenant_id>/<kind>/<yyyy>/<mm>/<uuid>.<ext>` — the tenant id is in
  the key **as defence in depth**, not as the access control (authorisation happens in
  the API against the database record, then a presigned URL is issued).
- Uploads are `server_generated_uuid` names; user filenames are stored as metadata only.
- Buckets are private; no public-read ACLs anywhere.
- Presigned download URLs expire in **5 minutes**; upload URLs in 10.
- MIME type and extension are validated against an allowlist; images are re-encoded and
  stripped of EXIF on upload.
- File metadata row: `id`, `tenant_id`, `kind`, `object_key`, `bytes`, `sha256`, `mime`,
  `original_name`, `created_by`, `created_at`, `deleted_at`.
- Deletion is soft (metadata row) → object removed by a job after the retention window,
  so an accidental delete is recoverable within the window and an export still works.

## Consequences

- Tenant export includes a manifest of files and presigned links, generated by a job.
- Platform admin cannot browse files without a break-glass grant (ADR-0014).
- Local development uses MinIO in Docker; if Docker is unavailable, a filesystem-backed
  adapter implementing the same interface is acceptable for tests only.
- Antivirus scanning hook: a placeholder `scan()` in the upload job, wired to a real
  scanner at M15 if the owner wants it.
